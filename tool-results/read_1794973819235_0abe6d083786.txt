   152→## 5. Today's plan
   153→
   154→### 5.1 The deterministic planner (must work with no AI, no account, no network)
   155→
   156→Pure module `src/lib/lumio/syllabus/planner.ts`:
   157→
   158→```ts
   159→buildSyllabusPlan(input: {
   160→  today: string;                       // learner-local yyyy-mm-dd (injected)
   161→  dayIndex: number;
   162→  slots: SessionSlot[];                // from planDayWithOverrides for today
   163→  subjects: SyllabusSubject[];         // visible subjects the learner takes (subjectPool ∩ visible)
   164→  compSub?: string;                    // complementary subject pairing
   165→  progress: Record<TopicId, TopicProgress>;
   166→  examDates: Record<subjectId, string | undefined>;   // from profile (nextExamDate etc.), may be empty
   167→  dueCardsCount?: number;
   168→}): PlanItem[]
   169→```
   170→
   171→- **Subjects per slot** come from the existing `subjectForSession` (keep complementary pairing).
   172→- **Topic priority score** (starting values; define them as named constants, document them in `docs/ARCHITECTURE.md`, and keep them easy to tune):
   173→  - Base by state: completed-but-not-confident **40**; completed with `lacks_practice` **35**; in progress **30**; not started **20** plus a small bonus for being the next topic in syllabus order (so the learner does not skip around); completed, unrated **15**; completed and confident **0**.
   174→  - Flag bonuses: `concept_unclear` +12, `lacks_practice` +10, `needs_revision` +8, `formulas` +6, `needs_help` +6, `speed` +5, `careless` +4.
   175→  - Marks weight: up to **+30** scaled by the unit's share of the subject's marks.
   176→  - Staleness: a completed-and-confident topic not reviewed for 21+ days gains up to **+15** (gentle spaced revision, so "confident" does not mean "forgotten").
   177→  - Exam urgency: if a subject's exam is within 30 days, scale the marks weight by 1.5.
   178→  - `formative_only` topics: multiply by **0.4**. `advanced` topics: multiply by **0.2**. Never exclude them.
   179→  - Anything already planned or touched today is skipped.
   180→- **Activity per item** is derived, not invented: not started or in progress means *Learn*; flagged `lacks_practice` means *Practise questions*; completed-but-not-confident or `needs_revision` means *Revise*; stale confident means *Quick recall*.
   181→- **Fit the slots:** estimate minutes per activity (named constants, for example Learn 35, Practise 25, Revise 15, Recall 10), fill each slot's length without overflowing, allow several short items per long slot, and never produce more than the slot count allows. If there are no slots today, return an honest empty plan ("No study sessions fit today. Open the Planner to adjust.").
   182→- Every item carries machine-readable **reason codes** (`NOT_CONFIDENT`, `LACKS_PRACTICE`, `HIGH_MARKS_UNIT`, `EXAM_SOON`, `STALE_REVISION`, `NEXT_IN_ORDER`, `IN_PROGRESS`, `CONCEPT_UNCLEAR`) rendered through i18n templates, so the non-AI plan is fully explainable. **Same inputs must always give the same plan** (deterministic tie-breaks by syllabus order).
   183→
   184→### 5.2 The AI refinement (optional, behind the existing gateway)
   185→
   186→If the AI gateway exists, add a feature `syllabus-day-coach` following its conventions (prompt file `prompts/syllabus-day-coach.v1.ts`, Zod schemas, `completeJson` with **one repair retry**, budgets, `ai_generated` labelling, the "AI" marker, "AI can make mistakes" line, a Report control). If the gateway does not exist yet, create only the `LlmGateway` interface and the **fake adapter** now, with the real adapter documented as future work in `INTEGRATIONS.md` (status `FAKE-ONLY`).
   187→
   188→- **Input to the model (privacy):** only the deterministic plan, the candidate topics (public syllabus ids and titles), their status and flag **enums**, unit mark shares, exam-proximity buckets (not dates), today's slot lengths, and the learner's **band**. **Never** send the name, email, user id, free-text notes (unless the learner ticks "Include my notes for this plan", off by default, sanitised and delimited as data), or raw dates of birth.
   189→- **Task:** reorder and re-balance the candidate items, pick the activity per item from the allowed enum, and write a **short encouraging reason (max 160 chars) per item** plus a one-sentence day summary, in the learner's language (English, Hindi, Hinglish), age-appropriate tone, never guilt-tripping.
   190→- **Output schema (Zod):** `{ summary, items: [{ slotIndex, topicIds[], activity, minutes, reason }] }`.
   191→- **Validation (hard rules, same module as the planner):** every `topicId` must exist in the candidate list; no duplicates; item count and total minutes must fit today's slots; subject must match the slot's subject; activity must be in the enum; reasons are length-capped and passed through the safe-Markdown renderer. **Any violation means discard the AI plan and show the deterministic plan** with a calm note ("Showing your standard plan"). The AI can never add topics, change marks or invent syllabus content.
   192→- **Degradation:** no key, signed out, over budget, provider down, invalid JSON after one repair: the deterministic plan shows with a calm reason; every non-AI path unchanged. The "Refine with AI" button appears only when the capability flag says AI is available and the learner has opted in.
   193→- **Never** claim board alignment beyond the syllabus data. The model has no tools and cannot fetch URLs.
