    21→

    23→

    29→- Operational machinery: nightly backups and restore drills, Prometheus/Sentry/observability, k6 load testing, Postgres/Redis production paths, object storage with signed URLs, virus scanning, EXIF and decompression-bomb defences, Docker production deployment guides.

    40→## 1. Operating rules (non-negotiable)
    41→
    42→- **R1 Truth in the UI.** This is the prototype’s best trait; keep and strengthen it. Every learning item carries provenance (author, source, licence, review status). Never invent official links, chapter lists, marks, rankings, friends, testimonials, user counts or ‘official’ badges. Sample content, AI-generated content and unreviewed content are labelled as such on screen. Official board links are validated by a build-time link checker; if a link cannot be verified, omit it and say so in `docs/INTEGRATIONS.md`.
    43→- **R2 No secrets in the client.** API keys, signing secrets and provider credentials exist only on the server (or in a serverless function). The browser never calls a paid or keyed API directly. Provide `.env.example`; never commit real values.
    44→- **R3 Adapters for everything external.** Each external service sits behind a typed interface with at least a real adapter and a deterministic fake adapter. The fake adapter is the default in dev and tests. See Section 8.
    45→- **R4 Fail soft.** If a service is down, unconfigured, rate-limited, over budget or blocked by the browser, the learner sees a calm, specific message and a working alternative, never a blank screen or a stack trace.
    46→- **R5 Minors first.** Most users are children. Apply data minimisation, no third-party trackers or ads in any learner flow, parental consent flows, and age-appropriate language. Align with India’s Digital Personal Data Protection Act 2023 and its Rules (children are under 18; verifiable parental consent; no tracking or behavioural monitoring of children). Verify current commencement dates and obligations before claiming compliance, and state clearly that this is engineering alignment, not legal advice.
    47→- **R6 Accessibility is a ship gate.** WCAG 2.2 AA, keyboard-complete, screen-reader tested where possible, reduced-motion respected, colour never the only signal, touch targets at least 44 px (larger for the youngest band).
    48→- **R7 No slop.** See the anti-slop checklist in Section 6.6. Generic gradient-card dashboards, emoji used as icons, unexplained lorem-style microcopy, and default framework look are failures.
    49→- **R8 No stubs.** No lorem ipsum, no TODO in shipped paths, no buttons that do nothing. If something cannot be built, hide it or label it ‘Not available yet’ with the true reason, and list it in `docs/KNOWN_LIMITS.md`.
    50→- **R9 Test what you build, report what you could not.** Run the code. If your environment cannot run something (real devices, real SMS, paid APIs), say so explicitly and provide a manual test sheet.
    51→- **R10 Your knowledge of third-party APIs is dated.** Prices, quotas, endpoints and policies change. Before depending on any service, read its current official documentation if you can browse. If you cannot, isolate it behind its adapter and mark the entry `VERIFY` in `docs/INTEGRATIONS.md`.
    52→- **R11 Few questions.** State assumptions in `docs/ASSUMPTIONS.md` and proceed. Ask at most one batch of five questions, and only for true blockers.
    53→- **R12 Vertical slices, complete files.** Build thin end-to-end slices (UI, state, storage, tests) rather than layers. Never output files with ellipses or ‘rest unchanged’ placeholders.
    54→- **R13 Never lose learner data.** Ship a migration that imports a prototype `lumio-s1` localStorage export and a prototype `accounts.json`, `social.json` and `leaderboard.json`. Add export and import (JSON) for all users.
    55→- **R14 Licences.** Use only content you may use. NCERT, CBSE, CISCE and state-board materials are copyrighted: link to them, never scrape or redistribute them. Open material (for example OpenStax under CC BY, Wikipedia under CC BY-SA) needs correct attribution stored in the content’s provenance fields.

   104→### 3.1 Product
   105→
   106→AI-free, offline-first, no-cost learning app. Everything lives in the browser (`localStorage` key `lumio-s1`, one JSON object). An optional server provides leaderboard, social features, accounts and parent links. Content is **Lumio-written sample material**, labelled as such; there is no official curriculum, textbook or past-paper content, and the app says so.
   107→
   108→### 3.2 Learner types, bands and navigation
   109→
   110→- `S.cat` is `school`, `dropper` or `above`. `S.band` is one of `young` (Nursery to Class 5), `middle` (6 to 8), `sec` (9 to 10), `senior` (11 to 12), `dropper`, `above`.
   111→- Navigation keys: `home`, `study`, `games`, `progress`, `ach`, `board`. The `young` band sees only home, study, games, ach. Other screens are reached from within: `focus`, `social`, `account`, `settings`, `guardian` (parent summary), and each game.
   112→- Themes by time of day, hour boundaries configurable (`S.sch=[6,17,19]`): **morning** 06:00 to 16:59 (light, indigo), **evening** 17:00 to 18:59 (warm peach and red-orange), **night** 19:00 to 05:59 (dark). Manual override. A ‘calm’ mode disables animation (and honours `prefers-reduced-motion`). Collapsible sidebar on desktop; bottom navigation on phones.

   114→### 3.3 Onboarding wizard (per learner type, every step validated)
   115→
   116→- **School:** name (optional); board (CBSE, ICSE/CISCE, UP Board, Other State Board, NIOS, Other/International); state or union territory (for Other State Board; auto for UP Board); curriculum text for international; class (Nursery to 12); academic year (defaults to current Indian academic year); preferred language; subjects (board-, class- and state-aware catalogue plus custom); prescribed textbooks; school start and end; dinner; bedtime; other commitments; study time outside school (Classes 10 to 12, sets a 1.5x target); next school exam and date; competitive-exam goal and date (from Class 9); learning goal; complementary subject; guardian step by age (Nursery to 5: a guardian must confirm and summary sharing defaults on; 6 to 8: recommended, default on; 9 to 12: optional, default off).

   118→- **Above Class 12:** type of learner; area of interest (24 topic areas plus custom goal); level; goal; target date; hours per week; preferred time; bedtime; commitments; topics. Never asks for a parent’s phone number.
   119→- Validation: required fields, number ranges, future dates only, school end after start, mock score not above total. Answers generate the study schedule automatically; if the day is too full the app says so instead of guessing. Settings, Learning profile reopens the same wizard pre-filled and keeps all progress.

   121→### 3.4 Study Area (the learning loop)
   122→
   123→- **Chapter path** with four states: locked, available, completed, mastered. A chapter unlocks when the previous one is completed (best score of at least 1). Header search across chapters.
   124→- **Chapter page:** source line (who wrote it, not official), glossary, notes with **Listen** (read-aloud: sentence by sentence, pause/resume, saved speed, Hindi voice for Devanagari text), key points, mind map (built from notes, tap to expand), flashcards (tap to flip), revision checklist, quiz with per-question explanations.
   125→- **Consolidation:** two revision sessions per chapter; mock tests with review of missed questions and ‘flag’ of weak chapters (clearing a flagged chapter is rewarded); a 15-minute **complementary subject** session unlocked by a completed chapter.
   126→- **Practice engine:** spaced-repetition flashcards (Leitner, 5 boxes at 1, 2, 4, 8, 16 days, self-rated, cards built from attempted chapters, XP once per day); weak-topic hub; adaptive practice; mixed-topic revision (interleaving); legendary challenge; timed 60-second drills; error-analysis lab (five worked solutions); remedial lesson built from the learner’s own misses; mistake notebook with tags (concept gap, careless slip, calculation error, forgot the fact); question-paper section that holds only official links and a self-reported attempt log.
   127→- **Utilities:** printable worksheet with answer key; local note upload (.txt, .md; PDFs rejected with a clear message); study reminder (browser notification while the tab is open); Study Video (paste a YouTube link, watch beside notes); Board and class guide with assessment patterns and confidence lines; CBSE Class 11 Physics outline with official facts and a link to the official PDF.

   129→### 3.5 Games and labs (eligibility by band; read `vGames` for the authoritative gates)
   130→
   131→Number Hop, Match the Pictures, Spell the Word, Sharp Eyes (odd-one-out and patterns), Capital Challenge, History Timeline, Pendulum Lab, Fraction Puzzles, Ecosystem Builder, Projectile Lab, Algebra Challenges, Virtual Chemistry Lab (balancing equations with live atom counts), Genetics Lab (Punnett squares), Budget Planner, Circuit Lab (series, parallel, target current), Engineering Lab (beam support forces by moments), Dataset Explorer (made-up data), Build Your Own Spaceship, Coding Lab (JavaScript in a Worker with 2 s limit; Python in Pyodide with 3 s limit; tests; hints; three debugging exercises), AI Lab and AI Fairness Lab (made-up data, overfitting and bias), Web Workspace (HTML and CSS with sandboxed live preview and a checked challenge). Each game awards XP once (typically +20 or +25 for five correct in a row; +25 for a passing code exercise). Physics models are intentionally simplified and say so on screen:
   132→
   133→- Rocket: dv = Isp × g0 × ln(m0 / m\_dry), with m\_dry = hull + engine mass × count + payload + 0.08 × fuel; thrust-to-weight = thrust × count / (m0 × g0). Engines (thrust kN, Isp s, mass t): Chem-S 3000 / 310 / 3, Hydro-X 1800 / 420 / 3.5, Ion-Z 5 / 3000 / 1. Missions: low Earth orbit from the ground needs dv at least 9.0 km/s and thrust-to-weight above 1.2; lunar transfer from orbit needs 3.2 km/s and thrust-to-weight above 0.005. A winning design exists (for example 2 Hydro-X, 220 t fuel, 2 t hull, 1 t payload). Keep that solvability as a test.
   134→- Projectile, pendulum, Ohm’s law (series and parallel), beam moments, equation balancing (smallest whole numbers), Punnett crosses (nine verified): re-implement and unit test every formula.

   136→### 3.6 Core mechanics (must be preserved exactly unless Section 7 says otherwise)
   137→
   138→- **XP on quiz finish:** gain = max(0, score − previous best) × 10, plus 20 on the first scored attempt with score of at least 1. XP is for improvement only; repeating a perfect quiz gives nothing.
   139→- **Mastery:** best score equal to the number of questions is mastered; best above 0 is completed. Progress separates completion from mastery.
   140→- **Streak:** consecutive calendar days (device-local date) on which an XP-earning activity was completed; counts back from today, or from yesterday if today is not yet done. Opening the app does not count. Best streak is stored; milestones at 3, 7, 14, 30, 60 and 100 days.
   141→- **Scheduler:** per-day session slots from `plan` (start, session length, number of sessions defaulting to the band goal, 15-minute gaps, optional 1.5x on Sundays). A chapter session is locked until its slot starts and counts once per new chapter. Busy windows are school hours and dinner (45 minutes). Reschedule moves missed sessions to the next free time that avoids busy windows and bedtime, and reports how many were dropped. Also: 7-day plan, month calendar of studied days, adaptive daily target from the last 7 days.
   142→- **Weak-topic ranking** weights: 2 per missed question; 3 if quiz not passed, 1 if not perfect; 2 if flagged in a mock; 1 per missed flashcard; 2 if practice accuracy is below 60% over at least 3 attempts.
   143→- **Adaptive practice:** difficulty level starts 0.5 (0.9 for legendary), rises on correct and falls on wrong; next question is the unseen one whose difficulty is closest to the level, with a penalty for repeating the same chapter; 8 questions (6 legendary). **Legendary challenge** unlocks after mastering two chapters, two lives, +40 XP on first win only.
   144→- **Quests:** daily, weekly (week starts Monday) and monthly, computed from real activity, claimable once for XP, with four quest achievements.
   145→- **Achievements (about 21):** quest finisher, weekly champion, monthly master, quest hunter, focus starter, steady focus, first lesson, first mastery, streak milestones 3/7/14/30/60/100, path complete, legend, flashcard habit, revision starter, mock tester, fix the gaps, any-light learner (finished quizzes in all three themes).
   146→- **Focus (Lock-In wellbeing):** Pomodoro-style presets Short 15/3 (default for young and middle), Classic 25/5, Deep 45/10, Custom; 4-block cycle with a longer break; XP 5 per completed block, capped at 4 blocks per day; **Strict Mode** blocks Practice and Games, Leaderboard and Friends behind a mascot blocking screen and makes ending early a 10-second wait; auto-start when a timetable slot begins (only if the app is open, within the first 2 minutes); away detection through page visibility with a kind message; sessions survive reload; a block that ended while the app was closed for over 2 minutes is not counted; self-set daily time limit that shows a rest reminder and never locks; generated focus sounds (brown noise, rain-like noise, gentle tones) with Web Audio, no audio files; 7-day screen-time analytics. Timers use timestamps, not tick counts, so background-tab throttling cannot corrupt them.
   147→- **Guardian summary:** consent flag, this-device printable weekly report; with accounts, a parent sees a summary only while the learner’s consent is on.

   223→
   224→### 5.4 Event-sourced local-first data and sync
   225→
   226→Replace the prototype’s ad hoc `mergeState` with an append-only **event log**.
   227→
   228→- Every learner action is an immutable event: `id` (UUIDv7), `type`, `payload`, `deviceId`, `clientTime`, `tz`. Examples: `quiz.finished`, `card.reviewed`, `focus.block.completed`, `quest.claimed`, `game.won`, `session.rescheduled`.
   229→- Current state (XP, streak, mastery, due cards, achievements) is a **projection** computed by pure functions in `packages/domain`. Monotonic values such as XP and best scores are derived, never set directly.
   230→- Sync is the union of event sets, idempotent by event ID, so multi-device merge is automatic and safe. Settings and schedule fields use last-writer-wins per field with timestamps.
   231→- Uploaded notes sync only if the learner opts in (object storage). Everything else is stored locally first and queued for sync with exponential backoff.
   232→- Provide a one-time **legacy importer**: paste or upload a prototype `lumio-s1` export and it is converted to events, preserving XP, days, results, flashcards, mocks, mistakes and settings.
   233→
   234→### 5.5 Ranked and unranked play
   235→
   236→- **Unranked (default, offline):** graded locally, counts for personal progress, never for leagues or leaderboards.
   237→- **Ranked (online, account required):** the server issues an attempt (item IDs without answer keys), grades each answer as it arrives, returns the explanation, and writes the XP ledger entry itself. Offline attempts are queued as `unverified` and excluded from leagues. Keep the daily XP cap and anomaly flags (the prototype capped at 800 XP per day).
   238→
   239→### 5.6 Time and locale
   240→
   241→Store the learner’s IANA time zone. A ‘day’ is the learner’s local calendar day; weeks start on Monday; the Indian academic year runs April to March. Format dates and numbers with `en-IN` and `hi-IN`. Never compare dates as strings without normalising zone.

   362→## 8. External services, data feeding and real-world quirks
   363→
   364→This section is what turns the prototype’s ‘not possible here’ list into working, honest features. Follow it closely. Remember R10: verify current provider documentation, limits and pricing before depending on anything below.
   365→
   366→### 8.1 The adapter pattern (applies to every integration)
   367→
   368→In `packages/adapters`, define one typed interface per capability: `LlmGateway`, `SmsProvider`, `EmailProvider`, `PushProvider`, `OcrProvider`, `TtsProvider`, `AsrProvider`, `ObjectStore`, `YoutubeProvider`, `OpenDataProvider`, `CodeRunner`, `CaptchaProvider`, `ModerationProvider`. Each has:
   369→
   370→- one or more **real adapters** and a **fake adapter** (deterministic, fixture-driven, with failure injection through `FAKE_FAIL_RATE` and `FAKE_LATENCY_MS`);
   371→- a Zod config schema validated at boot, which prints a **capability table** (what is on, what is off, why);
   372→- exposure of capability flags at `GET /api/capabilities` so the interface shows or hides features truthfully.
   373→
   374→Every outbound call goes through one shared `callExternal()` wrapper that provides: a timeout (default 8 s; streaming LLM calls 60 s); retries with exponential backoff and jitter for idempotent calls only; a circuit breaker (open after repeated failures, half-open probe); a concurrency limit; a per-provider rate limiter that honours `429` and `Retry-After`; idempotency keys for sends (OTP, email, push); log redaction; metrics for latency, errors and cost; response caching with stale-while-error for read-only data; and a closed error taxonomy: `UNCONFIGURED`, `UNAVAILABLE`, `RATE_LIMITED`, `OVER_BUDGET`, `INVALID_RESPONSE`, `BLOCKED_BY_POLICY`, each mapped to a calm learner-facing message.
   375→
   376→Health: `/healthz` (liveness), `/readyz` (database and required adapters), and an authenticated admin page listing each adapter’s status, last success, error rate and quota used.
   377→
   378→### 8.2 Degradation matrix (implement and test every row)
   379→
   380→| If this is missing or failing | The app must |
   381→| --- | --- |
   382→| Backend unreachable | Stay fully usable from local data; queue sync; hide leagues and rooms with a plain reason |
   383→| No LLM key, provider down, or over budget | Hide or disable AI actions with ‘AI help is off’; every non-AI path is unchanged; authored hints stay |
   384→| LLM returns invalid structured output | One repair retry, then fall back to authored content |
   385→| SMS provider down | Offer email code or recovery codes; never reveal whether an account exists |
   386→| Email provider down | Queue and retry; show the message in-app |
   387→| Push unsupported or denied | In-app banner, optional email digest, and install guidance on iOS |
   388→| No speech voice for a language | Say which voice is missing and how to add it; use cloud TTS only if configured |
   389→| Pyodide fails to load | JavaScript exercises keep working; Python shows progress, retry and an offline message |
   390→| OCR unavailable | Offer pasted text instead |
   391→| YouTube embed blocked or disabled by owner | Explain it and offer ‘open on YouTube’ |
   392→| Open-data API down | Use the bundled snapshot, labelled ‘sample data’ with its date |
   393→| Storage full or evicted | Warn, request persistent storage, offer export |
   394→
   395→### 8.3 The LLM layer (optional, grounded, budgeted)
   396→
   397→**Principles.** Server-side only. A provider-agnostic gateway configured by `LLM_PROVIDER`, `LLM_MODEL`, `LLM_API_KEY`, `LLM_BASE_URL`; an OpenAI-compatible base URL also allows self-hosted models. Never hard-code a model name. Everything works with AI switched off.
   398→
   399→**Features** (each behind its own flag):
   400→
   401→1. **Tutor.** Socratic by default: a hint ladder before answers. Grounded by retrieval over approved content packs only (BM25 or embeddings). Out-of-scope questions are declined and the learner is told what the tutor can help with. Cites chapter IDs. Persona by band: young, at most two short sentences and read-aloud; school, concise; adult, detailed. Replies in the learner’s language (English, Hindi, Hinglish).
   402→2. **Explain my mistake.** Given the item, the learner’s answer and the key, explain at the learner’s level and propose a remedial item.
   403→3. **Question and lesson generator** (a content-tools CLI plus an admin review queue). Generates items to the schema with concept tags, difficulty, hints, explanations and rationale for each distractor. Automated checks: a second-pass independent solve must agree with the key; numeric answers in maths and physics are verified by executing code in a sandbox; readability fits the band. Output status is `ai_generated_unreviewed`. It reaches learners only in a labelled beta practice mode until a human marks it `reviewed`.
   404→4. **Document to notes and flashcards,** for the learner’s own uploaded text, labelled ‘AI summary of your document’, with per-document consent.
   405→5. **Video notes,** from a learner-pasted transcript or consented speech-to-text (see 8.6).
   406→6. **Study-plan suggestions** returned as structured data and validated against scheduler constraints. The deterministic scheduler stays the source of truth.
   407→
   408→**Engineering requirements.**
   409→
   410→- Structured outputs: JSON Schema, Zod validation, one repair retry, then fail soft. Stream tutor replies over SSE.
   411→- Prompts are versioned files in `packages/adapters/llm/prompts/` with tests. No prompt strings scattered in code.
   412→- **Prompt-injection defence:** uploaded documents and retrieved text are data, delimited and never treated as instructions; the model has no tools and cannot fetch URLs; output is sanitised (safe Markdown, no raw HTML, no auto-loaded images or links).
   413→- **Child safety:** a minor-specific system policy; a moderation pass on input and output for under-18 users; a supportive, non-judgemental response with trusted-adult and helpline guidance when a learner expresses self-harm or abuse (verify current India helpline details before publishing); no romantic, violent or adult content; no personal advice beyond learning.
   414→- **Privacy:** no names, phone numbers or emails in prompts (scrub, and use pseudonymous IDs); choose provider settings that do not train on learner data and document it; store AI outputs only as long as needed.
   415→- **Budgets:** per-user daily token cap, per-IP cap, a global monthly cap with alerts, and a cost log. Cache generation tasks by hash of prompt version plus content version.
   416→- **Evaluation harness:** a golden set of at least 100 cases per feature with rubrics (correctness against the content, refusal when out of scope, safety, language fidelity). Runs in CI against the fake gateway and nightly against the real one.
   417→- Label every AI output with an ‘AI’ marker and a ‘Report a problem’ control.
   418→- **STEM quirk:** models make arithmetic and unit errors. Verify numeric answers programmatically. **Board quirk:** models are unreliable about specific Indian board syllabi. Ground in content packs and never claim board alignment the content does not have.

   420→### 8.4 Feeding data: the content pipeline
   421→
   422→**Schema** (Zod, in `packages/schemas`):
   423→
   424→- *Chapter:* `id`, `boards[]`, `classes[]`, `subject`, `title{en,hi,hinglish}`, `prerequisites[]`, `concepts[]`, `lessons[]` (typed blocks), `glossary[]`, `keyPoints[]`, `flashcards[]`, `items[]`.
   425→- *Item:* stable `id` (ULID), `type`, `stem{lang}`, `media[]` (with alt text and licence), `options[]`, `answer`, `unit` and `tolerance` for numeric, `explanation`, `hints[3]`, `difficultyAuthored` (1 to 5), `concepts[]`, `bloom`, `timeSec`, `provenance`.
   426→- *Provenance:* `author`, `createdAt`, `source` (`type`: `original`, `ai_generated`, `open_licence`, `official_link` or `licensed`; plus `url`, `title`, `licence`, `attribution`), `reviewStatus` (`draft`, `ai_generated_unreviewed`, `peer_reviewed`, `teacher_reviewed`), `reviewer`, `reviewedAt`, `version`.
   427→
   428→**Formats and importers** (`packages/content-tools`): YAML and Markdown as the native format; importers for CSV, XLSX, JSON, GIFT and Moodle XML (formats teachers already use), and optionally QTI 2.1. Importers produce schema-valid files or a per-row error report; they never write half-valid content.
   429→
   430→**CLI commands:**
   431→
   432→- `content:validate`: schema; unique IDs; answer index in range; no duplicate or empty options; distractor sanity; reading level for the band; blocked-word list for children; media alt text and licence present; KaTeX compiles; Devanagari renders; links valid.
   433→- `content:build`: compile immutable, hashed packs by board, class and subject with a manifest; compress; size budget of 300 KB per pack.
   434→- `content:import`, `content:generate` (LLM, Section 8.3), `content:link-check`, and `content:report` (a coverage matrix: chapters × items × percent reviewed).
   435→
   436→**Sources policy:**
   437→
   438→| Source | Allowed use | Quirk |
   439→| --- | --- | --- |
   440→| Lumio-original (human) | Preferred | Record author |
   441→| AI-generated | After validation, labelled | Reviewed before any ‘reviewed’ status |
   442→| OpenStax | Reference and explanations for Class 11 to 12 and adult topics | Most titles are CC BY 4.0; check each book’s licence page; attribute; its curriculum is not Indian-board aligned, so map concepts and never claim alignment |
   443→| Wikipedia and Wikimedia | Short glossary snippets and images | CC BY-SA share-alike; per-file licence metadata; attribute and link |
   444→| NCERT, CBSE, CISCE, state boards, NIOS | **Link out only** | Copyrighted; never scrape or redistribute. If an institution holds a licence, support importing a licensed pack (`source.type: licensed`) with the licence note stored; disabled by default |
   445→| Past papers | Official links and the learner’s own attempt log only | Do not host or copy |
   446→| Teacher or learner content | Private packs by default | Ownership and consent; moderation before any public sharing |
   447→
   448→**Volume target for this build.** Port every prototype chapter and question into the schema verbatim with ‘Lumio-written’ provenance. Then deliver a complete vertical slice: CBSE Class 11 Physics (the five Lumio-written chapters expanded to at least 30 items each across three difficulty tiers, with worked examples), at least one chapter per other band, and the Python chapter. Ship the generation pipeline so volume can scale, and report the coverage matrix honestly.

   450→**Versioning and delivery.** Packs are immutable and content-hashed. A manifest endpoint lists them. When an item is removed keep a tombstone so history stays valid.
   451→
   452→**Calibration feed.** A nightly job aggregates anonymised attempts (item ID, correct, time) and updates item difficulty once an item has at least 30 attempts. No personal data in the aggregate.

   473→### 8.7 YouTube and media (Study Video, video notes)
   474→
   475→- Playback uses the **IFrame Player API** (no key needed), preferably through the privacy-enhanced embed domain. Handle embed errors (video removed, embedding disabled by the owner, age-restricted) with a clear message and an ‘open on YouTube’ link.
   476→- The Data API (needs a key and has a daily quota; verify current numbers) is used only for metadata by video ID. Avoid search calls because they cost far more quota than lookups.
   477→- **Captions are the trap.** Downloading captions through the official API requires authorisation by the video’s owner, so there is no official way to fetch an arbitrary video’s transcript. **Do not** scrape transcripts or use unofficial libraries (terms-of-service risk and constant breakage). Offer these honest paths: the learner pastes a transcript; the learner uploads audio they have rights to, processed by the speech-to-text adapter with explicit consent; or timestamped manual notes (note stored with the current player time).
   478→- Never download videos. For the youngest band, disable free-form links and offer only a teacher or parent-approved list.
   479→- This feature does not block YouTube elsewhere, and the UI says so.
   480→
   481→### 8.8 Speech
   482→
   483→- `speechSynthesis` quirks: the voice list loads asynchronously (wait for `voiceschanged`); some browsers cut long utterances, so chunk by sentence (the prototype does); iOS needs a user gesture; Hindi voices depend on the device. Detect a voice by `lang` starting with `hi`, show a precise message when none exists, and use the optional cloud TTS adapter if configured.
   484→- Cloud TTS: pre-generate audio for static content at build time and store it content-hashed; for dynamic text cache by hash of text plus voice to control cost.
   485→- `SpeechRecognition` is not available in all browsers and often needs a network and microphone permission. Use it only for optional spelling or pronunciation games, always with a keyboard alternative, never storing audio.
   486→- Autoplay policies: unlock the `AudioContext` on the first gesture. Keep the generated focus sounds (brown noise, rain-like noise, tones) and give them a volume control.
   487→
   488→### 8.9 Files, PDF and OCR
   489→
   490→- Limits and checks: default 10 MB; detect type by magic bytes, not by extension; reject executables and archives; guard against decompression bombs; strip image EXIF location data; store in the object store under random keys with private access and short-lived signed URLs; optional virus scan (ClamAV).
   491→- PDF text extraction in the browser (PDF.js in a Worker). If a PDF has no text layer, route to OCR.
   492→- OCR: Tesseract.js (WebAssembly, English plus Hindi language data, lazy-loaded and cached) or a server OCR adapter. State plainly that handwriting and low-quality scans work poorly.
   493→- Extracted text stays on the device by default. Sending it to an AI feature needs explicit per-document consent. Warn against uploading images of people or identity documents.
   494→
   495→### 8.10 Code execution
   496→
   497→- **JavaScript:** a Worker or sandboxed iframe, terminated on timeout. Apply a strict CSP and **write a test proving that `fetch`, `XMLHttpRequest` and `WebSocket` fail inside the sandbox**; do not assume it.
   498→- **Python:** self-hosted, pinned Pyodide in a Worker, with an integrity check. Stop runaway code by terminating the Worker and reloading from cache. (Pyodide’s interrupt mechanism needs cross-origin isolation headers that can break third-party embeds such as YouTube, so do not enable isolation globally.) Show download progress; respect `navigator.connection.saveData` and warn on metered data before a roughly 10 MB first download.
   499→- **SQL:** SQLite compiled to WebAssembly in the browser.
   500→- **Other languages (optional, off by default):** a server runner adapter for a self-hosted sandbox such as Judge0 CE or Piston, with CPU, memory and time limits, no network, a queue and per-user rate limits.
   501→
   502→### 8.11 Messaging (India-specific quirks)
   503→
   504→- **SMS OTP:** transactional SMS in India requires sender and message-template registration under the TRAI DLT framework, and providers expose it differently. The adapter therefore takes `templateId` and variables, and config includes `SMS_SENDER_ID`, `SMS_DLT_ENTITY_ID`, `SMS_OTP_TEMPLATE_ID`. The prototype prints codes to the console when no provider is set; keep that **only** outside production, and make production refuse to start with phone sign-in enabled and no real provider.
   505→- **OTP security:** 6 digits, hashed at rest, 10-minute expiry, 5 tries, resend gap, per-phone and per-IP limits, identical responses whether or not the account exists. Guard against **SMS pumping** (fraudulent traffic to premium numbers): cap sends per number, per IP and per country prefix, add CAPTCHA before sending, and alert on spikes.
   506→- **Email:** adapter for a transactional provider or SMTP; document SPF, DKIM and DMARC; handle bounce and complaint webhooks with a suppression list; separate transactional mail from the weekly digest; include a one-click unsubscribe. Use Mailpit in development.
   507→- Prefer email or passkeys for adult learners and phone mainly for parents. WhatsApp OTP is optional and needs approved templates.
   508→- **Web Push:** VAPID keys and the `web-push` library; delete a subscription on a `410 Gone`; ask permission only after a user gesture and a plain explanation; quiet hours and per-category toggles; minimal payloads with nothing sensitive. iOS and iPadOS deliver Web Push only to a PWA installed to the Home Screen (16.4 or newer); Android battery optimisation may delay delivery; browsers cannot schedule local notifications reliably, so scheduled reminders come from a server job.
   509→
   510→### 8.12 Identity, sessions and abuse
   511→
   512→- Password hashing with argon2id (or scrypt with documented parameters). Session cookies `HttpOnly; Secure; SameSite=Lax`, CSRF tokens on state-changing requests, rotating sessions, a device list with revoke.
   513→- Lockout plus a privacy-friendly CAPTCHA adapter (for example Cloudflare Turnstile or hCaptcha) after repeated failures; the prototype had none. Optional breached-password check through a k-anonymity range API so the full hash is never sent.
   514→- Optional Google sign-in (OIDC) for adults only. Under-18 accounts always follow the parent flow.
   515→- Rate limits by IP and by account; honour `TRUST_PROXY` behind a proxy.
   516→
   517→### 8.13 Storage, PWA and browser quirks (handle and test each)
   518→
   519→- **Safari storage eviction:** script-writable storage of a site not installed to the Home Screen can be cleared after about seven days without use. Call `navigator.storage.persist()`, show install guidance, remind learners to sync or export, and verify behaviour on real iOS.
   520→- `QuotaExceededError`: catch it, tell the learner, never store blobs in `localStorage`.
   521→- **Service worker updates:** show ‘New version available’ and never swap versions during an active quiz or focus block.
   522→- iOS has no install prompt event: show manual ‘Add to Home Screen’ steps.
   523→- **Timers** are throttled in background tabs: use timestamps, the Page Visibility API and the Screen Wake Lock (re-acquire after visibility changes; not supported everywhere).
   524→- Use `100dvh` and safe-area insets. Regex lookbehind failed on Safari before 16.4 in the prototype: add a lint rule and a compatibility test, and provide fallbacks for `color-mix()`. Declare support as the last two versions of Chrome, Edge and Firefox, Safari 15.4 or newer, and Samsung Internet; test on a low-end Android phone with about 2 GB of RAM.
   525→- **Dates:** the prototype used a locale trick to produce `YYYY-MM-DD`. Replace it with one date utility that takes an explicit time zone.
   526→- **Clock skew:** server time is the truth for ranked play, leagues and rooms. Never trust client time for them.
   527→- **Multiple tabs:** use Web Locks or `BroadcastChannel` so only one tab writes state, runs a focus timer or auto-starts a block.
   528→- **Networks:** school and corporate networks may block YouTube or Google Fonts (self-host fonts); Indian mobile data is variable, so keep packs small, use skeleton screens, retry with backoff and honour the data-saver setting.
   529→- **Notifications denied:** the app must work fully and explain how to re-enable.

   531→### 8.14 Observability, analytics, deployment and backups
   532→
   533→- Structured logs (for example pino) with PII redaction and request IDs; Prometheus-style metrics; alerts on adapter failure rate and AI cost.
   534→- Error reporting (Sentry-compatible) optional, with scrubbing, no session replay, and off by default for minors unless a parent consents.
   535→- Product analytics: self-hosted, aggregate only, no cross-site identifiers, no behavioural profiling of children.
   536→- `.env.example` grouped as: core (`PORT`, `BASE_URL`, `NODE_ENV`, `DATABASE_URL`, `SESSION_SECRET`, `TRUST_PROXY`); limits (`RATE_PER_MIN`, `REGISTER_PER_HOUR`, `XP_DAY_CAP`); LLM (`LLM_PROVIDER`, `LLM_MODEL`, `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_DAILY_TOKENS_PER_USER`, `LLM_MONTHLY_BUDGET`); SMS (`SMS_PROVIDER`, `SMS_API_KEY`, `SMS_SENDER_ID`, `SMS_DLT_ENTITY_ID`, `SMS_OTP_TEMPLATE_ID`); email (`EMAIL_PROVIDER`, `SMTP_URL`, `EMAIL_FROM`); push (`VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`); storage (`S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`); other providers (`OCR_*`, `ASR_*`, `TTS_*`, `YOUTUBE_API_KEY`, `NASA_API_KEY`, `DATA_GOV_IN_API_KEY`, `WIKIMEDIA_CONTACT`, `CAPTCHA_SITE_KEY`, `CAPTCHA_SECRET`, `SENTRY_DSN`); backups (`BACKUP_DIR`, `BACKUP_KEEP`, `BACKUP_EVERY_MS`).
   537→- At boot validate config, print the capability table, and **refuse insecure production settings**: non-HTTPS base URL, default or short secrets, dev OTP mode on.
   538→- Backups: nightly database dump and object-store copy to a different location, retention policy, and a **tested restore drill** documented in `docs/`.

   550→### 10.1 Accessibility (WCAG 2.2 AA is a release gate)
   551→
   552→- Everything operable by keyboard with a visible focus indicator that is never hidden behind sticky UI (2.4.11); target size of at least 24 px by rule and 44 px by our standard (2.5.8); **drag alternatives** for ordering and timeline games (2.5.7); consistent help placement (3.2.6); no re-asking known information (3.3.7); **accessible authentication**: allow paste and password managers, no puzzle-only CAPTCHA (3.3.8).

   560→
   561→- Externalise every string (ICU MessageFormat with plurals).    595→### 12.1 The chunk protocol (non-negotiable)
   596→
   597→1. **One chunk at a time, in order.** Finish chunk N completely — including its gate — before starting chunk N+1. Never leave a chunk half-built at a chat boundary.
   598→2. **End-of-chunk output in chat.** After finishing a chunk, output in the chat: (a) complete code of every file created or changed in this chunk (complete files, no ellipses, no ‘rest unchanged’ — this extends R12 to chat output); (b) a file tree of everything built so far; (c) the chunk report in the Section 14 shape; (d) the current content of `PROGRESS.md`.
   599→3. **Pause.** Then stop and wait for the user’s explicit ‘continue’ before starting the next chunk. If the user opens a new chat instead, the resume path in 12.2 must work.
   600→4. **End-of-chunk files on disk.** At the end of every chunk, update two files at the repository root:
   601→   - `PROGRESS.md`: a status table of the five chunks (Done / In progress / Not started); the list of files built so far, grouped by chunk, one line per file; known issues and bugs; decisions taken (with a pointer to the Decision Log); the exact next steps for the next chunk. Keep it under about 200 lines so it is easy to paste into a new chat.
   602→   - `RESUME.md`: a ready-to-paste continuation prompt for a fresh chat (template in 12.2).
   603→5. **Never rely on chat memory.** Write every file to disk in full, and record every assumption in `PROGRESS.md` or `docs/ASSUMPTIONS.md` as you go, so a fresh chat can continue with no other context.

   622→## 14. How to work and how to report
   623→
   624→1. Start by replying with your understanding of the task, your assumptions, and the Phase 0 plan. Ask at most one batch of five blocking questions, then proceed.
   625→2. Work in vertical slices and run everything you build. If your environment cannot execute code, say so up front and deliver complete files phase by phase.
   626→3. Report each phase in this shape: **What changed**; **Parity delta** (rows passing and failing); **Evidence** (test summary, screenshot paths, Lighthouse and axe numbers); **Decision Log entries added**; **Risks and unverified items**; **Next**.
   627→4. Never claim something is tested when it was not run, or that a real provider works when only the fake was used. Label each integration VERIFIED, FAKE-ONLY or UNTESTED.
   628→5. When credentials are missing, use the fake adapter, keep going, and document exactly where the user plugs in real keys.
   629→6. Protect the prototype’s strengths: honest labelling, XP-once rules, improvement-only XP, the kind tone, no dark patterns.
   630→7. Prefer correctness of the learning mechanics and accessibility over decoration, but visual quality is part of the job and is judged against the anti-slop checklist.
